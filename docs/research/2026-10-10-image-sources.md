# Fallback card image sources (2026-10-10)

Research for the data-quality run: which secondary sources can fill the prints that have no `image_key`, under which terms, and how each would plug into `apps/api/src/import/images.ts` / `scripts/mirror-images.ts`. Coverage numbers are measured against the dev catalog (same as prod) on 2026-10-10. Every quote is verbatim from the page cited, fetched on 2026-10-10 unless marked as taken from `docs/marketing/card-imagery-legal.md` (fetched 2026-10-09). This is general information, not legal advice. Rights in the card art itself sit with The Pokémon Company / Wizards / Konami whatever the source; this note is about what each **source** allows on top of that (fact sheet §3 and §7 cover the rights holders).

## 1. Pokémon

### 1.1 pokemontcg.io v2 (now Scrydex)

**Coverage.** I matched all 1,627 keyless prints against the legacy data dump (github.com/PokemonTCG/pokemon-tcg-data, last push 2026-09-17, 176 sets, includes `me55` 30th Celebration and `me55c` Classic Collection): set by name (plus `30th-c`→`me55c`, `svp`, `sve`), card by number with leading zeros stripped, and by name for the two Classic Collections (their numbers are the original cards' numbers). Then I sent a HEAD to every one of the 911 matched image URLs. 858 answer with a real image; 53 answer 404 (McDonald's 2014/15/17/18 48, XY promos 3, one HGSS and one SVP promo). Full sets covered: Shiny Vault 122/122, Dragon Majesty 78/78, Shining Legends 78/78, Galarian Gallery 70/70, SM promos 67/67, the four Trainer Galleries 120/120, Skyridge 32/32, Aquapolis 32/40, 30th Mew B/G/R 3/3, 30th Classic Collection 28/30 (the two "Darkrai & Cresselia LEGEND" halves need a manual pick), Celebrations Classic Collection 25/25, McDonald's 2011/12/16/19/21/22, EX trainer kits 44/44, Best of Game 9/9. Not covered: MEP (0/112), My First Battle, all BW/HS/XY/SM/DP trainer kits, Unown Collection, Mega Evolution Energy, McDonald's 2023/24, Yellow A Alternate, Poké Card Creator Pack, SVP above 165 (the dump stops at 165; the image host has 196, 199, 200).

The image host answers a missing card with a **Pokémon card back** (PNG, 186,316 bytes, SHA-256 `fd7c3800f9b8ebadf4b31a735f569a180e66201741b00fafa17879967884ad2c`): with status 404 on `images.pokemontcg.io`, but with **status 200** on `images.scrydex.com` (for example `me55c-1`, `me55c-2`, `mep-001`). A mirror must reject that body by hash, not by status.

**Status and limits** (https://docs.pokemontcg.io/getting-started/rate-limits): "The Pokémon TCG API is deprecated. New account registrations are no longer available." "Existing API keys will continue to function through March 1, 2027." "Please migrate your application to Scrydex." Without a key: "You are rate limited to 1000 requests a day, and a maxium of 30 per minute." With a key: "By default, requests are limited to 20,000/day." The data repo README: "The Pokémon TCG API is scheduled to be taken offline on March 1, 2027." and "Existing data in this repository will remain available for historical and compatibility purposes." The repo has no licence file (GitHub reports `license: null`). The docs footer: "This website is not produced, endorsed, supported, or affiliated with Nintendo or The Pokémon Company." pokemontcg.io itself has no terms page (`/terms` 404); its home page says "The Pokémon TCG API is now part of Scrydex".

**Scrydex terms** (https://scrydex.com/terms, no date on the page): "Resell, sublicense, redistribute, mirror, or commercially exploit the Services without prior written authorization from Scrydex." and "Use the Services primarily as a substitute backend, proxy, or wholesale data source for a competing commercial product or service without written authorization from Scrydex." Governing law: "the laws of the State of Wisconsin."

**Scrydex image guidance** (https://scrydex.com/docs/getting-started/best-practices): "Caching image URLs or downloading and serving images locally significantly reduces dependency on API requests and external servers." "Hosting the images yourself (e.g., on your own Content Delivery Network (CDN)) ensures better control and reliability, particularly for high-traffic applications." "Never assume the urls -> they generally follow a specific pattern, but that is not guaranteed. Always reference the urls as returned by the API." "consuming images does not cost any credits". "Scrydex does not claim ownership of the images provided by the API. All images belong to their respective copyright holders".

**Pricing** (https://scrydex.com/pricing): Starter $29/month (5,000 credits), Growth $99/month, Professional $399/month; "There is no free tier".

**Assessment: ask.** Hotlinking is out anyway (our CSP allows only img.voidbinder.de). Self-hosting is what Scrydex's own docs recommend, but its terms forbid mirroring "the Services" without written authorization, and Voidbinder is a commercial product with collection features, so the "substitute backend … for a competing commercial product" clause could be read against us. The rights in the art are the same TPCi exposure we already carry with TCGdex. One email to Scrydex settles it; the answer also tells us whether the paid plan would cover MEP and the newer promos. Attribution: none required by either page; a "Pokémon images via pokemontcg.io / Scrydex" line next to our TCGdex credit is cheap.

### 1.2 TCGdex, other languages and Japanese

Already our source; terms as in the fact sheet §3 (TCGdex README: "The Database is licensed under the MIT License."; FAQ on rate limits: "There are no published hard rate limits, but please be considerate. … cache responses locally"). No rights in the images are granted or claimed.

- **Other languages:** 87 of the 1,627 prints have an image in another language in our own R2 already (`print_localizations.image_key`): Shining Legends 78/78 (de, it, es, pt have `https://assets.tcgdex.net/de/sm/sm3.5/1/high.webp`, en has none), Forbidden Light 6, plus `sm2`, `sv03.5`, `xy8` one each. All 87 are also in pokemontcg.io. A display-side fallback ("show the German scan when there is no English one") costs no new source, but it shows foreign text on an English print, so it is a product call, not a data fix.
- **Japanese:** TCGdex models Japanese releases as separate sets with their own ids and numbering (`M-P` "メガ プロモカード", 132 cards; `SV-P`, `S-P`, …). There is no mapping from an international print (`mep-001`) to a Japanese one, and none of the probe cards has a `ja` image under its international id. Not usable for these gaps.
- **30th B/G/R and three more:** TCGdex's API advertises an image that its asset host does not have (30th B/G/R in no language; `dc1-1`, `ex14-97`, `sv03.5-163` in en). All six are in pokemontcg.io. Worth reporting upstream (github.com/tcgdex/cards-database issues); our mirror logs these as failures on every run.

### 1.3 Limitless TCG

Has MEP (`/cards/MEP/1` with `MEP_001_R_EN_LG.png`), Shiny Vault (`/cards/SHF/SV1`), Galarian Gallery (`/cards/CRZ/GG1`). Card images sit in their own bucket under a `tpci/` path. Terms (https://limitlesstcg.com/legal): the page is an Impressum (Robin Schulz, Gdańsk, contact@limitlesstcg.com) plus the notice "The literal and graphical information presented on this website about the Pokémon Trading Card Game, including card images and text, is copyright The Pokémon Company (Pokémon), Nintendo, Game Freak and/or Creatures." There is no API for cards, no licence and no reuse grant; `robots.txt` disallows nothing, but that is not permission. **Usable: ask** (email the operator). I would not build on it: one person's scans, no stable URLs, no ids we hold.

### 1.5 TCGplayer product images (via TCGCSV ids in `price_mappings`)

Coverage: 765 of the 1,627 keyless prints have a `tcgplayer` mapping; 158 of those are prints pokemontcg.io lacks (MEP 75, My First Battle 24, SVP 27, Mega Evolution Energy 16, SV Energy 8, Aquapolis 8). `https://tcgplayer-cdn.tcgplayer.com/product/<id>_in_1000x1000.jpg` answered 200 for every probe (CloudFront; sizes 420×584 to 717×1000, so not a reliable 1000 px). Note that most of these mappings are `number_match` with TCGdex's own `mapping_confidence: "low"`.

Terms (TCGplayer Terms of Service, "Updated: September 27, 2023", read via help.tcgplayer.com's article API because the page answers 403 to fetchers): "All of the content found on TCGplayer.com and websites under the TCGplayer.com domain, including graphics, text, buttons, logos, video, audio, downloadable files, pricing information and card databases, are the property of TCGplayer, Inc. … This material may not be used in connection with any service or product outside of TCGplayer without express written permission". "You agree not to crawl, scrape or spider any of our websites without express permission from us." API docs (https://docs.tcgplayer.com/docs/getting-started.md): "We are no longer granting new API access at this time." and existing users must follow "important restrictions and attributions". TCGCSV (https://tcgcsv.com/faq) republishes the API data and says nothing about images. **Usable: no** without written permission from TCGplayer (eBay); not worth chasing for 158 prints.

### 1.6 Cardmarket

We hold Cardmarket ids, but Cardmarket offers no image source to third parties: "Currently, we are not accepting applications for access to the Cardmarket API" (https://help.cardmarket.com/en/cardmarket-api). Its site blocks automated fetching (fact sheet §6). **Usable: no.**

### 1.7 Malie.io, PokéGuardian

- PokéGuardian: a news site; its footer says the content is property of the copyright holders and "not affiliated with, sponsored or endorsed by" TPCi/Nintendo. No card database or terms for reuse. **No.**

## 2. Magic: Scryfall `image_status`

**Cause of all 3,635 gaps:** every keyless Magic print has `scryfall_images.highres_image = false`; `image_status` is `lowres` for 3,066 and `placeholder` for 569. `sourceUrl('mtg')` returns null unless `highres_image` is true, by design. A live check of 14 random gap prints against `api.scryfall.com/cards/<id>` returned the same status as our row, so the data is current, not stale. Biggest sets: 30th Anniversary Edition 594 lowres, LTR 465, LTC 432, TDC 411, TDM 403, Unknown Event 203, Foreign Black Border 183 lowres + 116 placeholder, Fourth Edition Foreign Black Border 376 placeholder, Chronicles FBB 72 placeholder + 45 lowres.

**Scryfall's definitions** (https://scryfall.com/docs/api/images): "missing — The card has no image, or the image is being processed. This value should only be temporary for very new cards." "placeholder — Scryfall doesn't have an image of this card, but we know it exists and we have uploaded a placeholder in the meantime. This value is most common on localized cards." "lowres — The card's image is low-quality, either because it was just spoiled or we don't have better photography for it yet." "highres_scan — This card has a full-resolution scanner image. Crisp and glossy!" Card object (https://scryfall.com/docs/api/cards): "highres_image — True if this card's imagery is high resolution."

**What the files look like:** the `large` file of a `lowres` print (30A Living Lands) is a normal 672×936 card image, a bit soft; fine at our 320 px `sm` size. The `large` file of a `placeholder` print (4BB Shapeshifter, Spanish) is the English card with a "Localized Image Not Available ES" badge across the art, also 672×936.

**Is a lower-res image acceptable?** Scryfall's image terms (fact sheet §2) make no distinction by status; they forbid altering the image ("Do not cover, crop, or clip off the copyright or artist name", no watermarks), not using a soft one. Mirroring `lowres` as is: **yes**. Mirroring `placeholder` as is: allowed and honest (the badge says what it is), but it shows English text on a foreign print; the alternative is to keep our own placeholder. `missing` (none today) should stay keyless.

**Catch:** our objects are stored with `public, max-age=31536000, immutable` under `images/mtg/<scryfall id>/<lang>/orig.jpg`. If a `lowres` image went to that key, the later high-res scan written to the same key would stay invisible behind caches for a year. So a non-highres image needs its own file name and the row must be re-mirrored when the status changes (Scryfall's URL carries a `?<timestamp>` that changes when the image does).

## 3. How each usable source plugs into the mirror

The key scheme stays `images/<game>/<sourceId>/<lang>/{orig.<ext>,sm.webp}`; the source id stays the **primary** source's id (TCGdex card id, Scryfall id), so a fallback image lands where the primary image would have, and dev and prod still share objects.

**Pokémon, pokemontcg.io fallback** (only after Scrydex says yes):

1. Data: in the TCGdex importer (`apps/api/src/import/tcgdex/`), add `ptcg` (pokemontcg.io card id) and `ptcg_image` (its `images.large`) to `prints.external_ids`. Source: the GitHub data dump (`cards/en/<setId>.json`, no key, no rate limit) refreshed with the TCGdex import; or the API without a key (1,000 requests/day is enough for ~50 set queries) to reach cards the dump lacks. Matching: a small TCGdex-set → pokemontcg.io-set table (the ids are not derivable: `swsh4.5sv`→`swsh45sv` but `swsh12.5gg`→`swsh12pt5gg`, `30th`→`me55`, `30th-c`→`me55c`, `2021swsh`→`mcd21`, `bog`→`bp`, `tk-ex-latia`→`tk1a`), number with leading zeros stripped, and by card name for `me55c` / `cel25c`. Matching by name across the whole set table, as in this research, finds most pairs; keep the table explicit.
2. `sourceUrl('pokemon')`: `tcgdex_images.high` first, then `ptcg_image`. For the 30th B/G/R case (TCGdex URL exists, file 404s), the job needs the second URL too: give `ImageJob` an optional `fallbackUrl` and let `download()` try it on a 404. `sourceId('pokemon')` already prefers `ids.tcgdex`, so the key becomes `images/pokemon/30th-B/en/orig.png`.
3. `extension()`: `images.scrydex.com/pokemon/<id>/large` has no file extension, so `planJobs` would count it as "no source". Take the extension from the response `content-type` (the host sends `image/png`) or default `png` for this host.
4. Placeholder guard in `download()`: reject a body whose SHA-256 is `fd7c3800…ad2c` (the card back above), even on status 200, and count it as "no source", not as a failure to retry forever. `crypto.subtle.digest` works in both the Worker delta and the Node script.
5. Rate: both image hosts are Cloudflare-cached with `immutable`; the existing `pokemon: 8` per second bucket is fine.
6. After 2027-03-01 the free API is gone and the dump is frozen; new sets would then need the Scrydex plan or stay on TCGdex only.

**Magic, non-highres Scryfall images:**

1. `sourceUrl('mtg')`: accept `lowres` (and, if Max wants it, `placeholder`) instead of returning null; never `missing` or the `errors.scryfall.com` URL.
2. Key: write those under a different file name, e.g. `images/mtg/<id>/<lang>/orig-lowres.jpg` and `sm-lowres.webp` (and teach `hasSm` that name), so the later `highres_scan` goes to `orig.jpg` / `sm.webp` and is not hidden by the year-long immutable cache.
3. Re-mirror: the pending-rows query must also pick rows whose `image_key` is a `-lowres` key while `scryfall_images.highres_image` is now true; the Scryfall import already refreshes `external_ids` daily.

**Not plugged in:** TCGplayer, Cardmarket, pokemon.com, pokemon-card.com, Limitless, Malie (terms, §1.3 to §1.7). TCGdex other languages need no mirror change (the objects exist); they would be an API/display fallback.
